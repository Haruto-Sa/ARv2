# P1 技術検証チェックリスト(iPhoneで試す)

対象: `docs/ar-spec.md` §11 P1。各ライブラリの「使える／使えない」を判定するための手順。
数値・主観的な印象の両方を、各セクションの表に書き込みながら進める。

## 共通の準備

- 実機: 手元のiPhone(Safari)。協力が得られれば他の端末も。
- 通信: README記載の `npm run dev` + `cloudflared tunnel --url http://localhost:<port>` の手順でiPhoneから開く。
- 各spikeは**別々のgitブランチ**にある。ブランチを切り替えてから `npm run dev` し直すこと(同時に全部は見られない)。
- `spike/alvaar` はGPLv3。**pushしない・mainに入れない**(`docs/ar-spec.md` §10.3)。ローカルで動作確認するだけにとどめる。

```bash
git checkout spike/mindar      # または spike/fiducial / spike/alvaar
npm run dev
# 別ターミナルで
cloudflared tunnel --url http://localhost:<ポート番号>
```

表示された `https://*.trycloudflare.com/lab/spike/<name>/` をiPhoneで開く。

## 1. spike/mindar(MindAR 画像ターゲット追跡)

URL: `/lab/spike/mindar`

1. `public/lab-assets/mindar/target.png` をもう1台の画面に表示するか印刷する。
2. 「カメラを開始」をタップ → カメラ許可。
3. target.png にカメラを向け、緑の立方体が重なって表示されるか確認する。

| 項目 | 記録 |
|---|---|
| 追跡できたか | |
| 追跡が安定するまでの時間 | |
| fps(画面左上の表示) | |
| 角度・距離を変えても追従するか | |
| 実写真(合成画像でなく)でも試した場合の結果 | |

> 合成画像(target.png)はテスト用。実際の看板・銘板の写真が用意でき次第、
> `public/lab-assets/mindar/README.md` の手順で作り直して再検証すること。

## 2. spike/fiducial(js-aruco2 印刷マーカー)

URL: `/lab/spike/fiducial`

1. `/lab-assets/fiducial/marker-0.svg` を印刷する。印刷した一辺の実寸(mm)を測る。
2. ページの「マーカーの実寸(mm)」に測った値を入力する。
3. 「カメラを開始」→ カメラ許可 → マーカーにカメラを向ける。

| 項目 | 記録 |
|---|---|
| 検出できたか | |
| fps | |
| 表示される位置(x,y,z mm)は実際の距離感と合っているか | |
| **認識できる最大距離**(マーカーから離れていって記録) | |
| 認識できる角度の範囲(正面から何度まで) | |
| 誤差(dbg-err)の目安値 | |

## 3. spike/alvaar(AlvaAR SLAM)⚠️ GPLv3・ローカル限定

URL: `/lab/spike/alvaar`

**このブランチはpushしない。ローカルで動作確認するだけ。**

1. 「カメラを開始」→ カメラ許可。
2. 特徴の多い場所(机の上、本棚など)でゆっくり端末を動かし、トラッキングが安定するのを待つ。
3. 緑の立方体が実世界の同じ場所に固定されて見えるか確認する。
4. 立方体が見えている状態で、20歩ほど歩いて戻ってくる。

| 項目 | 記録 |
|---|---|
| 床(または平面)を検知できるか | |
| 置いた位置からのずれ(目視) | |
| fps | |
| 60秒静止時のドリフト | |
| 20m歩いて戻った後のずれ | |
| iPhone Safariで動いたか(動かない場合はエラー内容) | |

## 判定の目安

各ライブラリについて、以下のどちらかを `docs/ar-spec.md` の§11完了条件に沿って記録する:

- **使える**: 上記の記録が実用に足る(fps・精度・安定性)
- **使えない**: 具体的にどの指標がだめだったか(例: 2m以上離れると認識しない、など)

次のステップ(P2〜)に進む前に、この結果を本体の報告と合わせてどのスパイクを
本線候補にするか判断する。
